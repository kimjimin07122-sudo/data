# uavprep — UAV 결함 탐지 데이터셋 공통 전처리 모듈

세 데이터셋(ALFA, UAV-SEAD, 연구실 데이터셋)을 **같은 원칙**으로 처리해 **같은 형식의 학습 행렬**로 만든다.
설정 파일 하나로 원본 → 윈도 행렬(npz) + 정규화 파일 + 설명 파일(meta.json)까지 한 번에 만든다.

> ⚠ 연구실 데이터셋(Ahn et al., 2026)은 서약서 대상이다. 이 저장소에는 **reader 코드만** 있다.
> 데이터, 라벨(labels.json), 출력 npz는 허가된 PC 밖으로 옮기지 않는다. `.gitignore`에도 막아 두었다.

---

## 1. 사용법

```bash
pip install -r requirements.txt          # numpy, pandas, pyulog(UAV-SEAD만)
# configs/<데이터셋>.json 의 raw(원본 경로), out_npz 등을 자기 환경에 맞게 고친 뒤
python -m uavprep.build configs/alfa.json
python -m uavprep.build configs/uav_sead.json
python -m uavprep.build configs/ardu.json
```

| 데이터셋 | 원본 | 받는 곳 |
|---|---|---|
| ALFA | 공식 `processed.zip` (토픽별 CSV) | figshare 12707963 (CC0) |
| UAV-SEAD | `.ulg` + `mapping.json` (Normal, Mechanical만 있으면 됨) | HF `aykutkabaoglu/uav-flight-anomaly-dataset` (CC BY 4.0) |
| 연구실 | 메시지별 CSV 폴더 + `labels.json` | 연구실 내부 (서약서) |

## 2. 출력 형식

`out_npz` 하나에 세트(`normal`=학습, `valid`=검증, 결함 세트들)별로 들어 있다.

| 키 | 모양 | 내용 |
|---|---|---|
| `<세트>_X` | (N, L, C) | 윈도 [j, j+L)의 입력 채널, 학습 세트 기준 z-score |
| `<세트>_Y` | (N, 10) | 예측 대상 = 스텝 j+L의 **상태 10채널** |
| `<세트>_label` | (N, 2) | [정상, 결함] — 스텝 j+L 기준 |
| `<세트>_seq_length` | (시퀀스 수,) | 시퀀스 길이 S. 시퀀스당 윈도 수 = S − L |
| `<세트>_keys` | (시퀀스 수,) | 비행 이름. 지상으로 나뉜 조각은 `<비행>#<n>` |

- `*_norm.npz`: `mean`, `std`, `channels` (학습 세트 통계, 채널 이름 순서)
- `*_meta.json`: 설정, 제외한 비행과 **이유**, 버린 짧은 조각, 시퀀스별 길이·결함 스텝·지상 스텝·결함 시작 초

| 데이터셋 | 주기 | L (초) | 입력 C | 결함 세트 | 학습 / 검증 / 시험 윈도 (v0.4) |
|---|---|---|---|---|---|
| ALFA | 4 Hz | 24 (6.0 s) | 17 | engine, elevator, rudder | 7,039 / 1,910 / 4,717 |
| UAV-SEAD | 10 Hz | 64 (6.4 s) | 18 | mechanical | 1,000,066 / 261,960 / 67,033 |
| 연구실 | 5 Hz | 32 (6.4 s) | 16 | gps, imu, motor, vibration | (데이터 비공개) |

채널 (상태 10은 세 데이터셋 공통 = 측정 속도 3 + 자세 쿼터니언 4 + 각속도 3):

| | 지령 채널 |
|---|---|
| ALFA (17) | 지령 속도 3 + 지령 자세 쿼터니언 4 |
| UAV-SEAD (18) | 지령 각속도 3 + 추력 1 + 지령 자세 쿼터니언 4 |
| 연구실 (16) | 지령 자세 쿼터니언 4 + 스로틀 입력·출력 2 |

`~/ALFA/transformer/train_eval.py`(Tiny Transformer 예측기)가 이 형식을 그대로 읽는다(`--npz`, `--sets`, `--fault-sets`, `--n_in`, `--L`, `--dt`).

## 3. 처리 원칙과 이유 (원본 분석 근거)

수치는 공개 데이터셋(ALFA, UAV-SEAD)의 원본을 직접 분석한 결과다.

| # | 원칙 | 왜 (데이터 근거) |
|---|---|---|
| 1 | **출력은 상태 10채널로 고정**, 입력은 상태 + 그 데이터셋의 지령 채널 | 세 데이터셋 모두 속도·자세·각속도는 있지만 지령 채널 종류가 다르다. 예측 대상을 맞춰야 결과를 비교할 수 있다 |
| 2 | 자세는 **쿼터니언**으로, 요는 (−180°, 180°]로 접어 변환 | ALFA 47편 중 38편에서 요가 ±180°를 넘나든다. 오일러각을 그대로 쓰면 값이 360° 튄다. 부호 연속화도 시험했으나 ALFA AUROC 0.929 → 0.890으로 나빠져 쓰지 않는다 |
| 3 | **구간 = 모델 채널만으로 겹치는 시간** | UAV-SEAD 기존 변환은 모델에 안 쓰는 채널(지령 속도)까지 겹쳐 잘랐다. 이 채널은 결함 무렵 위치 제어가 꺼지면 기록이 멈춰서, **시험 결함 시간의 24%(27편)**가 빠져 있었다. 고치자 결함 후 포함 오경보가 15.8 → 23.4편으로 늘었다(기존 결과가 과소 보고) |
| 4 | **격자 주기 = 가장 느린 핵심 채널의 원래 주기** | ALFA는 각속도가 4.1 Hz, UAV-SEAD는 속도·지령 자세가 10 Hz다. 더 촘촘히 하면 같은 값이 반복될 뿐이다. ※ UAV-SEAD는 5 Hz가 10 Hz보다 AUROC 0.02 높았다 → 조정 여지 있음 |
| 5 | 빠른 채널은 **직전 구간 평균**, 느린 채널은 선형보간 | 마지막 값만 쓰면 20 Hz 토픽의 메시지 5개 중 4개를 버린다. ALFA에서 두 방식의 값 차이는 열 표준편차의 1~8%이고, 같은 판정 설정에서 성능 차이도 표준편차 안이다 |
| 6 | 핵심 채널이 격자의 절반보다 느리게 기록된 로그는 **제외** | UAV-SEAD 정상 비행 12편은 모든 토픽이 1 Hz로만 기록돼 있다. 보간하면 매끈한 가짜 데이터가 된다. 빼자 seed 사이 흔들림이 줄었다(탐지 편수 표준편차 1.4 → 0.4) |
| 7 | **문맥 길이 약 6초** (L = 6 s × 주기) | ALFA·UAV-SEAD 모두 기존 윈도 스윕에서 6.0~6.4 s가 가장 좋았다 |
| 8 | **지상 구간 제거**(착지·시동 꺼짐·모터 공회전·이륙 전 떠오르는 중), 끊긴 앞뒤는 별도 시퀀스 | 지상 구간은 지령이 상수라 정상 통계를 왜곡하고 오경보를 만든다. 특히 **이륙 전 과도 구간이 시퀀스 앞에 남으면 비행별 기준선(처음 10 s)이 오염**된다. UAV-SEAD는 PX4 착지 판정 기준 약 2%만 지상이고, ALFA는 원본이 자동비행 구간뿐이라 해당 없다 |
| 9 | 짧은 조각(< L + 10 스텝)은 버리되 **meta.json에 기록** | 기존 코드는 짧은 비행을 말없이 버렸다(UAV-SEAD 6편) |
| 10 | 결함 라벨 = 공식 라벨 출처에서 **시험 대상 결함 종류의 구간만** | UAV-SEAD 기존 라벨은 모든 주석의 합집합이라 Mechanical 비행에 위치·고도 이상 구간 8개가 섞여 있었다. 빼자 지연 20.4 → 14.2 s, 오경보 8.8 → 6.8 |
| 11 | 원본 결함 신호와 다른 라벨은 **고치거나 빼고 기록** | ALFA rudder 시험 3편 중 1편은 원본상 양쪽 에일러론 결함이다(러더 결함 신호 없음). 제외한다 |
| 12 | 학습·검증은 **정상 비행만**, 비행 단위로, 날짜(세션)가 있으면 **같은 날은 같은 세트로** | UAV-SEAD 무작위 배정에서는 검증 비행의 98.6%가 같은 날 학습 비행이 있었다. 날짜 묶음 배정 seed를 바꿔도 결과가 거의 같다(AUROC 0.760~0.766) |
| 13 | 정규화 = 학습 세트 평균·표준편차, 파일로 저장 | 검증·시험 정보가 새지 않게 |

### 데이터셋별 메모
- **ALFA**: 공식 processed 배포본에서 Park et al.의 MATLAB 가공본(46편 × 18열)을 **오차 0으로 재현**해 처리 방식을 확정했다(피치·요를 롤 메시지 순번으로 꺼내는 특이점 포함). 정상 학습 33편 중 23편은 결함 비행의 결함 직전까지 구간이다. 각 시퀀스의 처음 8 s는 버린다(Park, 제어기 안정화). 배정은 기존 논문과 비교하려고 Park 분할을 그대로 쓴다. 대기속도 센서는 34편에서 전부 0이라 쓰지 않는다.
- **UAV-SEAD**: 각속도는 PX4 버전에 따라 `vehicle_angular_velocity` 또는 `vehicle_attitude.*speed`, 추력은 `thrust` 또는 `thrust_body[2]×(−1)`. 최대 |속도| > 20 m/s 정상 비행 2편은 EKF 발산으로 보고 뺀다. 결함 뒤에도 비행이 이어지므로(46/47편) 평가 때 결함 후 구간 포함·제외를 둘 다 본다.
- **연구실 데이터셋**: GPS 지상속도·방위를 원래 주기에서 속도 벡터로 바꾼 뒤 격자로 옮긴다(방위 접힘 회피). 센서 번호가 섞인 메시지는 가장 많이 기록된 번호만 쓴다. 비행 없이 찍은 대리 기록(EMI, Heating)은 뺀다.

## 4. 대표 모델로 확인한 결과 (v0.4)

Tiny Transformer 예측기(파라미터 약 2.6만, 배치 192, Adam 1.3e-3, 100 에폭 / 조기종료 10, seed 5개). 잔차는 EWMA(β = exp(−dt / 1.3 s)), 임계값 = 검증 잔차 평균 + 3.291 × 표준편차.
결함 후 구간과 기준선이 오염된 비행을 뺀 평가 기준.

| 데이터셋 | 임계값 | AUROC | 시나리오 F1 | 탐지 | 오경보 |
|---|---|---|---|---|---|
| ALFA | 전역 | 0.929 | 0.944 | 11.8 / 12 | 1.2 |
| UAV-SEAD | 비행별 | 0.765 | 0.600 | 20.6 / 42 | 6.0 |

- ALFA는 기존 Park 가공본과 같은 판정 설정에서 차이가 표준편차 안이다(0.922 vs 0.929).
- β를 "검증 잔차 최댓값에 맞추는" 기존 규칙은 데이터 경계가 1~2스텝만 달라도 β가 0.83 ↔ 0.95로 바뀌어 ALFA F1이 0.96 ↔ 0.76으로 흔들렸다. 그래서 시간 상수(1.3 s)로 고정한다.
- 기체·조건이 하나인 ALFA는 전역 임계값이, 여러 기체가 섞인 UAV-SEAD는 비행별 임계값이 낫다.

## 5. 구조

```
uavprep/
├── core.py            격자·구간 평균·쿼터니언·지상 분할·윈도·정규화·저장 (공통)
├── build.py           설정 → reader → core → npz/norm/meta
└── datasets/
    ├── alfa.py        ALFA (토픽별 CSV)
    ├── uav_sead.py    UAV-SEAD (.ulg, pyulog)
    └── ardu.py        연구실 데이터셋 (ArduPilot 메시지별 CSV)
configs/               데이터셋별 표준 설정 (경로만 바꿔 쓴다)
models/                대표 모델·탐지 실험 코드와 결과 (models/README.md)
```

새 데이터셋을 넣으려면 `datasets/<이름>.py`에 `load_all(cfg)`를 만들어 `({세트: [레코드…]}, 제외 목록, 상태 채널 이름, 지령 채널 이름)`을 돌려주면 된다.
레코드 = `dict(key, group, t, x(T×C), fault(T), ground(T), info)` — 시간축·지상 판정·라벨까지는 reader가, 나머지는 core가 처리한다.
